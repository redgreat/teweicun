# 特维存 AI 编码规则

## 主入口

- 默认中文沟通。
- 根目录 `AGENTS.md` 是通用 AI 规则主入口。
- `MEMORY.md` 保存后续调试常用的长期项目记忆。
- `CLAUDE.md` 是 Claude Code 入口，内容应与 `AGENTS.md` 保持一致。

## 项目事实

- 特维存是进销存系统，面向特种设备/压力容器制造企业。
- 当前架构是 DB-First：复杂业务、事务、状态流转和库存一致性优先在 PostgreSQL 中实现。
- 后端：Go + Gin + pgx/pgxpool + Zap + Viper。
- 前端：`frontend/`，SvelteKit 2 + Svelte 5 + TypeScript + Tailwind + DaisyUI。
- 数据库迁移：`sql/migrations/NNN_description.sql`。

## 必守约束

1. 禁止 ORM，数据库访问只用 pgx/pgxpool + 手写参数化 SQL。
2. 核心流程优先调用存储过程/函数/视图，例如 `CALL sp_xxx(...)`、`SELECT fn_xxx(...)`。
3. 数据库变更必须新增迁移，不要直接改 `sql/schema.sql`。
4. 新增迁移头部必须包含 `-- MIGRATION_ID: <唯一ID>` 和 `-- MIGRATION_APPLIED: pending`。
5. 新增数据库对象和列要补中文 `COMMENT`。
6. 可空字段和 LEFT JOIN 字段要处理 Go Scan 空值问题：SQL `COALESCE` 或 Go 可空类型。
7. 不要在文档、日志、回答中复述配置文件里的密码、Token、密钥。

## 调 bug 路线

1. 前端页面：`frontend/src/routes/**/+page.svelte`。
2. API client：`frontend/src/lib/api/client.ts`，成功响应按 `code === 0` 解包。
3. 路由：`cmd/server/main.go`。
4. 后端链路：`internal/handler` -> `internal/service` -> `internal/db`。
5. 数据库线索：`sql/migrations/`、`sql/schema.sql`、相关 `sp_`/`fn_`/`v_`。

## 高频问题

- `cannot scan NULL into *string`：检查 SQL 可空列、LEFT JOIN、Scan 类型。
- 库存异常：查 `quantity`、`locked_quantity`、`in_transit_quantity`、库存流水和相关确认过程。
- 单据状态异常：查数据库过程状态机和 Go 层是否重复调用/漏传用户。
- 前端分页错乱：检查父组件是否用 `bind:page` 同步 `DataGrid` 页码。
